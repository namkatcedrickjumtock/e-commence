Anti-pattern 1 · the lesson

We Learned to Stop Stamping Our Name on Every Error

Under-wrapped ⬥Sweet Spot Over-wrapped

Every layer stamps its name

The root cause is buried under paragraphs of prefixes you already have in your logs.

Root cause + minimal context

Enough to trace the origin. Not so much that the signal gets buried.

Tells you nothing

The error is too vague to know where it came from or what caused it.

  if p.mode == ModeCardDeclined {
    return &StripeError{
      RequestID:  "req_7NdMtHtVhh5i2J",
      Type:        "card_error",
      Code:        "card_declined",

services/checkout.go — Checkoutv0.1
func (s *service) Checkout(ctx context) (*CheckoutOutput, error) {
  if err := s.payments.Charge(ctx, total); err != nil {
    return nil, fmt.Errorf("payment processing failed: %w", err)
  }

  order, err := s.repo.CreateOrder(ctx, persistence.Order{TotalCents: total, Items: items})
  if err != nil { return nil, fmt.Errorf("order creation failed: %w", err) }

  return &CheckoutOutput{OrderID: order.ID, TotalCents: order.TotalCents}, nil
}

Translate at the boundary

what leakedStripeError

persistence — the fixv0.2
func (p *StripeProvider) Charge(...) error {
  err := stripe.Charge(ctx, amount)
  if isDeclined(err) {
    return &PaymentError{
      Code: "payment_declined",
      Retryable: false,
    }
  }
}

StripeError never leaves the persistence package. It becomes a domain type your clients can depend on.
